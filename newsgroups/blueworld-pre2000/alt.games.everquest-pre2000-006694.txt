By ORB, you talking about "Object Request Broker"?  Like the CORBA standard
that IBM uses.  And DCOM that microsoft uses?

Anyway, that Chris Bryant guy didn't have a firm grasp of the point of my
original message.  (Nor do I think he has even a loose grasp of software
engineering.)  The poster I replied to was talking about "process
clustering" -- where one machine on a network is constantly informed of the
load status of all the other machines.  If Machine A is quite busy and
happens to notice that Machine B is not busy, Machine A can request to have
B take over some of it's processing load.  That's what process clustering is
all about, which is what the original poster was trying to talk about.

However, Win32 does not support this.  Win32 does support a type of "load
balancing" -- when a process (not a thread) is about to start up, it checks
to see who's the lightest loaded machine and runs the process on that
machine using DCOM techniques.  A lot of clustered Unix variants do this as
well.

So, basicly what I was trying to get across is that it's a futile effort to
make that happen for EQ, since Win32 doesn't support it.  I think the Linux
Wolfpack cluster over in Austria is trying this...I can't remember the
details of how their doing this.  They re-wrote like 70% of the kernel to do
it.
