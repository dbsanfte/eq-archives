As I use different UNIX flavors at work (also Linux, although Linux
isn't actually part of UNIX family, it is a mere lookalike), I can
indeed point out that:

- "man" pages are from hell, hard to use, hard to navigate etc. etc.
compared to good GUI help system. And if you try to use "man -k" and
it fails, it is not intuitive to think that you must run "catman"
command.

- "vi" is pretty much the only text editor you can count that every
UNIX box has (no, they don't always have emacs or others), and vi is
very hard and unintuitive to use. 0 takes you to the beginning of a
line? And $ takes you to the end of the line? Makes sense? No? It is
supposed to, I guess. Just keep pressing that Esc.

- The way how in unix file names are differentiated with upper case
and lower case, it causes much more trouble than it's worth. This
caused us trouble e.g. when we e.g. tried to install software to our
clients' machines with a CD-ROM, and the conventional install
procedure didn't work because the machines thought all the file names
on the CD were in upper case, which they weren't. So we had to install
them manually (had to use certain -cdcase option).

I really don't get the idea behind that upper case/lower case thing in
unix, it is TOTALLY WORTHLESS feature that causes NOTHING BUT TROUBLE.
Whenever you mention some file name to someone else that he should
check (for example Text.LOG), you can't just say "look at the file
text.log", but instead "the filename is text.log, first t in upper
case, LOG in upper case, everything else in lower case".
