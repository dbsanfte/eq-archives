Okay, we are now getting into the s/w engineering world...

If you use a Unix "like" OS and not windoz, the line between processes
(read threads for windows enthusiasts) running on the same machine or
another machine gets blurred. QNX via its global name locator can make
is easy to dynamically shift processes from box to box on a network to
balance load. i.e. in a Win32 environment it would be like sending a
message to another named thread and not knowing or caring whether that
thread is running on the same box or another box. I have never
implemented this type of thing in Win32 and am not sure it would even be
possible due to the lack of a central network "global" name management
task.  Although, I suppose this could be mimiced by using DNS and socks
in a crude manner.  QNX is easier because it deals with communications
at the send/receive call level and doesn't require going through tcp/ip
and sockets overhead.

This is where the "flexibly distributable" comes in. The ability to
easily shift tasks from box to box to balance processing load. I in EQ's
case it appears that each "zone" runs as a separate process.

I suggest you pick up a book on Unix and multi-processing networked
environments to find out more. Computer literacy probably has some
selections.
