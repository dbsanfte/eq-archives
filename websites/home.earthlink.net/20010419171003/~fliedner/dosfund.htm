DOS FUNDAMENTALS

DOS is an acronym for Disk Operating System. Several different companies programmed their own version of DOS, the A+ test covers Microsoft's version, called MS-DOS. MS-DOS was improved and enhanced over the years, these improvements/enhancements coming in the form of 'Versions' of DOS. The last version that was sold was 6.22.

An operating system (OS) must perform several important tasks for the computer.

    • It must be able to communicate with all the various pieces of hardware that are installed in the computer. This communication is how the hardware is made to do whatever it is supposed to do.
    • It must provide a user interface, that is, a way for the user of the computer to issue commands to the OS. These commands will allow the user to run programs or to manage the operation of their computer.

 

COMMUNICATING WITH HARDWARE

The system BIOS issues instructions to all the basic pieces hardware included with the computer. When a user operates their computer, what ends up happening is the hardware is made to do some sort of work. Commands have to get issued to the hardware telling it what to do. Since the user is interacting with the computer through the OS, the OS has two choices: it must issue commands to the BIOS, so the BIOS can in turn issue the commands to the hardware; or it can issue commands directly to the hardware. Early Oses, like MS-DOS, would issue commands to the BIOS. Newer Oses, like Windows, would do both. Which commands are direct and which are indirect is not important.

The system BIOS can't contain commands for every possible piece of hardware, it would be incredibly large if it did. Plus, if new hardware comes out after a BIOS is programmed, the BIOS would be obsolete until it got reprogrammed. So when additional pieces of hardware are added to a computer, they need to bring their own instructions so that the system BIOS and the OS know how to communicate with and give instructions to the hardware. These instructions are called DEVICE DRIVERS or just DRIVERS.

 

PROVIDING A USER INTERFACE

A user interface provides the user with a way to issue commands to the OS, and a way for the OS to communicate information to the user. A user will issue a command in order to make the OS perform some task. Tasks include running a program, copying data onto a floppy disk, getting a hard drive ready for use, as well as many, many more that we will learn.

The DOS interface is text based. All commands the user issues to DOS must be typed on the keyboard. DOS is not case-sensitive, meaning that DOS makes no distinction between upper and lower case letters. When the user types in a command to DOS, the <ENTER> key must be pressed. This 'sends' the command to DOS, letting DOS know the user is done typing and it's now DOS's turn. A lot of DOS commands require the user to include additional information on the same line as the command (before the user presses the <ENTER> key). There must be one or more spaces in-between the DOS command and each additional piece of information, or else DOS won't know where the command ends and the additional information begins.

 

DRIVES, DIRECTORIES, AND FILES

DRIVES

Hard drives, floppy drives, CD-ROM drives, ZIP drives, tape drives. All these drives store data. Think of these drives as digital filing cabinets. Regular filing cabinets have structure to help you organize your files, as do the computer's drives.

Every drive in a computer needs an identifier. DOS uses the letters of the alphabet and a colon (such as 'C:') to identify each drive. A: and B: are reserved for floppy drives. Hard drive partitions get the next letters, starting at C: and continuing until all partitions are lettered. The primary partition of each physical drive gets the first available letters. Then the first physical drive's logical drives are lettered, followed by the other physical drive's logical drives. The CD-ROM drive gets the next available letter, then other drives like ZIP, network, and RAM drives. You will always be 'in' a drive while using DOS, meaning DOS' attention is focused on that drive. The proper way to change from one drive to another is by typing in the drive letter of the drive you want to go to, and a colon. So if you were in the C: drive and wanted to go into the A: drive, you would just type in A: and press <ENTER>.

DIRECTORIES

A directory is a place to store files within your drives. Every drive has at least one directory, called the root. The root directory is represented by the backslash ( \ ) character. Directories must follow the same naming rules as files, including extensions. Most directories don't have an extension, but it is perfectly legal within DOS to have one. It is customary practice to create directories as a place to store a group of files that are related in some way; for example all the files that make up DOS are stored together in a directory called 'DOS'. No other files should be stored there (but there is nothing preventing you from doing that). The root directory has a limitation that no other directories have - there can be no more than 512 files and/or directories within the root directory.

Directories contain mostly files, but it is possible to place one directory into another directory. So you can place DirectoryB into DirectoryA. DirectoryB is it's own directory, but it can also be called a subdirectory (of DirectoryA).

You will always be 'in' a directory, whether it is the root or some subdirectory.

There are several commands that allow you to work with directories.

    • MKDIR, or MD, will make a new directory. The directory you make will automatically be a subdirectory of the directory you are in, unless you tell DOS otherwise.
    • RMDIR, or RD, will remove a directory. The directory you're trying to remove must be empty of all files and subdirectories, and you can't be in the directory you're trying to remove.
    • CHDIR, or CD, will change which directory you are in (it will move you from one directory into another).
    • DIR will display the contents of the current directory, showing all files and subdirectories (but not the contents of the subdirectories). You'll also notice two entries that seem to make no sense. There will be a single period that is flagged as a directory. This is a shortcut that represents the current directory. There will also be a double period, which represents the next higher (or parent) directory. These shortcuts will be useful from time to time when issuing certain DOS commands.

FILES

The data on these drives needs to be identified, organized, and cataloged. The basic unit of data storage on these drives is a file. Files contain different types of data. Some files have instructions that make up the OS; this document you're reading was created on a computer that was using the Windows98 operating system. A bunch of files on my computer's hard drive make up Windows98. Some files have instructions that make up programs (also called applications); this document you're reading was created in a program called 'Word'. Several of the files on my hard drive make up Word. Some files contain data that the user has created; this document is stored in a file called 'DOS FUNDAMENTALS.doc'.

All OSes have rules concerning files, as well as commands that work on files. First the rules…

    • All files need a name. This is how the files are identified and kept track of. DOS allows the name to be anywhere between one and eight characters (letters, numbers, and a few special characters are allowed. Spaces and the / \ [ ] | < > + = ; , * ? characters aren't allowed).
    • Files can have an extension, but this is optional. The extension can be between one and three characters long. Extensions are added to the end of the file name, separated from the file name by a period.
    • The purpose of the extension is to signify what kind of file it is, meaning what kind of data is within the file.
    • A file's name must be unique within the directory (which we'll discuss next) that the file resides in.

Think of the things you can do to a paper file. You can copy it, you can throw it away, you can move it from one place to another. You can do all these actions to computer files as well, if you know the proper command. Here are DOS's file commands…

    • COPY - This command will make a copy of an existing file. The copy can have the same name as the original, or it can be given a new name at the same time as it is being copied. The copy can be placed in the same directory as the original (but only if it is given a new name at the same time), or it can be placed into a different (existing) directory.
    • REN - This command will rename a file.
    • DEL - This command will delete a file.
    • MOVE - This command will move a file from one directory into another.
    • XCOPY - This command works just like COPY, but it works a little bit quicker, and it can do a few extra things COPY can't do.

 

DOS STRUCTURE

There are three files that make up the core (which can also be called the kernel) of DOS. These files have instructions to allow DOS to do what it is supposed to do. The files are named IO.SYS, MSDOS.SYS, and COMMAND.COM. Once these three files are copied into your computer's memory, and the instructions that are inside the files are carried out, DOS is active on your computer, and in control.

    • IO.SYS handles communicating with basic I/O devices.
    • MSDOS.SYS handles disk operations.
    • COMMAND.COM creates the user interface. When the user types in a command and hits the <ENTER> key, COMMAND.COM receives the command and decides what to do. It is also called the command interpreter. Some commonly used DOS commands are actually contained within COMMAND.COM, these are called internal commands. Any command that is not internal is considered to be external.

There are two other files that are used when DOS is loading. These files are optional, meaning DOS will load just fine even if one or both of the files are not present. These files must be named CONFIG.SYS and AUTOEXEC.BAT, and must be in the root directory of whichever drive the system is booting from. Both of the files contain plain text commands (the files haven't been converted to computer language).

CONFIG.SYS

The primary purpose for CONFIG.SYS is to load device drivers. Any device attached to your computer (either inside or outside) that is not part of the motherboard will need it's own driver. A driver is really just a file that has instructions (in computer language) for the OS to be able to communicate with and give commands to a particular piece of equipment. A driver is loaded by using the DEVICE= or DEVICEHIGH= statement, followed by the location and name of the device driver file. Some other settings that are set via CONFIG .SYS:

    • FILES=XX. This determines how many files DOS can have open at once.
    • BUFFERS=XX. This sets aside a certain number of temporary storage areas for data that is being read from or written to disks.
    • LASTDRIVE=Z. This will allow DOS to use all possible drive letters.
    • SHELL= This sets the location of the command interpreter, but more importantly increases the environment space beyond 256 bytes.

AUTOEXEC.BAT

Any file that ends in .BAT is a batch file, which DOS considers to be an executable file. Batch files allow you to create your own 'program'. You enter into a batch file as many DOS commands as you want, when the batch file is run, each command will be carried out in the order it appears inside the file. AUTOEXEC.BAT is a special batch file that is automatically run when the DOS loads. You load a special type of device driver via AUTOEXEC.BAT, called a TSR (Terminate and Stay Resident). TSRs load into memory and quietly hang out in the background, waiting for a certain event to happen that will spring the TSR into action. An example would be a mouse driver. DOS doesn't have built-in support for mice, so you need to load a DOS mouse driver before you can use a mouse from DOS. If you load a mouse TSR into memory, it will sit quietly in the background, waiting for you to actually move your mouse, as soon as you do the TSR will activate & let DOS know you have moved the mouse & it needs to reposition the mouse pointer on the screen.

TSRs are loaded with the LOADHIGH (or LH) statement, followed by the location of and name of the TSR file. Or you can omit the LOADHIGH (or LH) and just specify the location and name of the file.

Here are a few other settings made via the AUTOEXEC.BAT file:

    • SET is used to set environment variables. This is a little piece of data that any program can view and use in any way it needs to.
    • PATH is used to set the search path. This tells COMMAND.COM which directories to search, and in what order, whenever it has to look for an external command.
    • PROMPT is used to set how the command prompt looks.

 

BOOTING A DOS COMPUTER

Booting means powering on a computer. A DOS computer will have the following boot sequence:

    • IO.SYS is loaded into memory.
    • MSDOS.SYS is loaded into memory.
    • CONFIG.SYS, if present, will be processed.
    • COMMAND.COM is loaded into memory.
    • AUTOEXEC.BAT, if present, is processed.

 

THE DOS INTERFACE

DOS lets the user know it is ready to be commanded by presenting the user with a prompt. The prompt can be customized, which we'll go over later on, but the default look for the prompt is to show the drive, path, and a greater than symbol ( > ). For example, C:\DOS>_. This tells us that we are in the C: drive, in a directory called DOS that is a subdirectory of the root. Each directory listed in the path will be separated by the backslash character. The first backslash (the one right after the colon) represents the root directory, the rest of the backslashes just separate one directory name from the next.

You interact with DOS by typing in a command. This command tells DOS what you want it to do now. COMMAND.COM, the command interpreter, receives the command you typed in, and will be responsible for attempting to carry out your command. The command will first be checked to see if it is an internal command. If not, then the current directory is checked to see if there is a file with a name that matches what you typed in. If not, then the search path is searched (in the order specified in the PATH statement from the AUTOEXEC.BAT file and stored in the environment). If a match isn't found then you will get a 'Bad command or file name' error. At any time during the search, if a file is found whose name matches what you typed in, then that file will be copied into memory and then executed.

There are three types of executable files in DOS: files whose names end in either .COM, .EXE, or .BAT, and that is the order of precedence. So if you typed in FORMAT, and COMMAND.COM found a file called FORMAT.COM and another one called FORMAT.EXE in the same directory, FORMAT.COM will be the file that gets executed.

 

DOS MEMORY

The 8088 processor that the first version of DOS was designed to work with could address 1MB of RAM. This 1MB was divided into two separate areas, conventional and reserved.

CONVENTIONAL MEMORY

The first 640KB of RAM is called conventional memory. This is where DOS (IO.SYS and MSDOS.SYS) is located while the computer is running. This is where device drivers can be located. Whatever space is left is available to load a single program into, once loaded the program can be executed (run). In the early days of computers, programs weren't that large, so 640KB was plenty of memory, with room to spare. But as programs got more complex (and contained more instructions, which took up more space), this 640KB limit started becoming a problem. This is where memory management comes into play, which we'll discuss shortly.

RESERVED or UPPER MEMORY

The next 384KB of RAM is considered to be reserved (or upper) memory (640KB + 384KB = 1024KB or 1MB). The system (motherboard) BIOS will be copied to here, as well as video card BIOS. There will be unused space as well. This space can be utilized to store some drivers that would normally be stored in conventional memory. This unused space is called Upper Memory Blocks, or UMB.

To let DOS know that you will be loading drivers into reserved memory (using UMB), you must add the following line anywhere in the CONFIG.SYS file:

    • DOS=UMB

EXPANDED MEMORY (EMS)

DOS is limited to working within the first 640KB of RAM. When a program, and the data that the program was working on started needing more than 640KB, something had to be done to give these programs more memory. Lotus, Intel, and Microsoft (LIM) invented expanded memory for this purpose. Expanded memory is RAM that is mounted to an expansion card. Now the CPU isn't programmed to directly access RAM that is sitting on an expansion card, so a special program has to be loaded into conventional memory that will be able to access the RAM that is on the expansion card. This program is called the expanded memory manager, the original version was named EMM.SYS (it is now called EMM386.EXE). EMM.SYS could address up to 8MB of RAM on the expansion card. EMM would use 64KB of reserved memory to create a page frame, consisting of 4 16KB pages. DOS programs had to be written to utilize this expanded memory; once EMS was made available almost all DOS programs were.

Expanded memory works like this: The data that the program is actively working on must be in one of the pages in reserved memory. The rest of the data will be stored in expanded memory. If some new or different data is required, the program will clear one or more of the pages to make room. The data in the cleared pages goes back to expanded memory until it is needed again (or the program is exited). The program is responsible for keeping track of where in expanded memory the data is located. But it must request EMM to store and retrieve the data.

EMM386.EXE is loaded into conventional memory via the CONFIG.SYS file, with an entry like this:

    • DEVICE=C:\DOS\EMM386.EXE

This will load the EMM386 file into conventional memory. EMM386 will then make reserved memory available and create the 64KB page frame there. As an alternative, you could use the following line:

    • DEVICE=C:\DOS\EMM386.EXE NOEMS

This will load the EMM386 file into conventional memory. EMM386 will then make reserved memory available, but it will not create the 64KB page frame and therefore not be able to access and use expanded memory.

EXTENDED MEMORY (XMS)

Regular RAM installed in your motherboard's RAM slots that is beyond the first 1MB is extended memory. So in a computer with 64MB of RAM, 63MB would be considered extended. Extended memory isn't directly accessible from DOS, it needs a memory manager. HIMEM.SYS is the name of the extended memory manager. HIMEM.SYS performs three tasks:

    • Controls access to expanded memory. Any program wanting to use expanded memory must access it via HIMEM.SYS.
    • Creates the High Memory Area (HMA), which is the first 64KB of extended memory. This special area can be accessed by DOS, and is typically used to store a portion of DOS code.
    • Can make extended memory emulate (pretend to be) expanded memory, making expanded memory cards obsolete.

HIMEM.SYS is loaded into conventional memory via the CONFIG.SYS file, with an entry like this:

    • DEVICE=C:\DOS\HIMEM.SYS

This is usually the first or second line of the CONFIG.SYS file. It must be before the line that loads EMM386.EXE.

To give DOS 'permission' to use the HMA, add the following line to the CONFIG.SYS file:

    • DOS=HIGH

You can also use the following: DOS=HIGH,UMB to kill two birds with one stone.

 

DOS MEMORY MANAGEMENT

Now that we have learned about the different types of memory DOS uses, and how to make each type available, we need to discuss memory management. The goal of DOS memory management is to make as much conventional memory available (unused) as possible. The newer the DOS program, the bigger it was (generally), and the more free, unused conventional memory it needed. If a program file was 570KB in size, but you only had 560KB of unused conventional memory, you wouldn't be able to run that program until you made at least 10 more KB of memory available. You make conventional memory available by loading drivers into reserved memory.

First off, some parts of DOS have to be in conventional memory. IO.SYS, MSDOS.SYS, COMMAND.COM, HIMEM.SYS and EMM386.EXE will not go into reserved memory even if you tried to make them. So you will never have 640KB of free conventional memory. Realistically, 600KB to 620KB is all you'll be able to get.

Most device drivers don't care if they're loaded into conventional or reserved memory. The ones that do care will simply not go into reserved memory when told to, but will go into conventional memory instead. To tell a driver to go into reserved memory, use the following command:

    • DEVICEHIGH=

After the =, you need to type in the path to and name of the device driver you're loading. For example:

    • DEVICEHIGH=C:\CDROM\OAKCD.SYS
      C:\CDROM\ is the path, and OAKCD.SYS is the driver.

This command only works inside the CONFIG.SYS file, which is where most of your device drivers will be loaded.

To load a driver from the AUTOEXEC.BAT file into conventional memory, simply type in the path to and name of the driver. For example:

    • C:\MOUSE\MOUSE.COM

To load a driver from the AUTOEXEC.BAT file into reserved memory, type in LOADHIGH (or LH for short) before the path & driver name. For example:

    • LH C:\MOUSE\MOUSE.COM

By loading drivers into reserved memory, they aren't occupying conventional memory. This is the goal of memory management.

MEM.EXE

This DOS program displays memory utilization; how much of each type of memory you have, how much is used, and how much is available.

MEM with the /C switch (and you'll want to use the /P switch at the same time) will give you a detailed analysis of which programs are loaded into memory, and where they are (between conventional and upper).

MEMMAKER.EXE

This DOS program will perform memory management for you automatically. It analyzes which drivers you are loading during boot up and sees where they wind up (in conventional or reserved memory). It then modifies your CONFIG.SYS and AUTOEXEC.BAT files, adding the DEVICEHIGH and LH to as many drivers as possible. If you weren't using EMM386.EXE to make reserved memory available, it will add the instruction to your CONFIG.SYS file to do so. It analyzes the size of reserved memory, and uses as much as possible, by putting whichever drivers into the UMB that will utilize the most possible space.

 

OTHER DOS INFORMATION

Some additional DOS information that you'll need to know. The A+ exam is only concerned with DOS versions 5.0, 6.0, 6.20, 6.21 and 6.22. Some thing covered here might not apply to earlier versions of DOS, or will be slightly different in earlier versions. Don't concern yourself with the earlier versions.

FILE SYSTEMS

All operating systems support one or more file systems. A file system is the method used to organize and store data on floppy, hard, and CD-ROM drives. The file system that DOS uses is called FAT (technically FAT16). DOS is a 16-bit operating system, meaning the code that makes up DOS is written in 16-bit size. FAT16 is a 16-bit file system (to match the size of the operating system). This means, among other things, that FAT16 has 16 bits to use to make up all storage locations. Each storage location on a drive has to have an address, that is how the storage locations can be kept track of. With 16 bits available to create addresses, you can make 65,536 different addresses (take 2 and raise it to the 16th power to get 65,536). Hard drive sectors are always 512 Bytes in size. FAT16 can group 1, 2, 4, 8, 16, 32, or 64 sectors together into a storage unit called a cluster. So the maximum partition size that you can create using the FAT16 file system is 2,048KB (2.1GB). Let's do the math: 512 Bytes X 64 sectors = 32KB (32,768 Bytes). 32KB X 65,536 = 2,048KB.

MULTITASKING

Multitasking is the term used to describe an operating system that can run more than one program at a time. DOS is not a multitasking operating system.

WILDCARDS

A wildcard is a special character that can be used with any DOS command that works on files. There are two wildcard characters, the asterisk and the question mark. The * is used to represent any number of characters. The ? is used to represent any single character. Some examples:

    • To delete all the files in the current directory that end with DOC : DEL *.DOC
    • To rename all the files extensions in the current directory from DOC to WPD :
      REN *.DOC *.WPD
    • To move all the files that start with the letter C from the current directory to the TEMP directory : MOVE C*.* \TEMP
    • To move all the files whose names are exactly four characters long, that have any extension, to the A: drive : MOVE ????.* A:

FILE AND DIRECTORY NAMES

All file and directory names that are stored on a DOS computer can be no more than eight characters in length. A character is a letter or number, and some of the symbols. The following symbols can't be used / \ [ ] | < > + = ; , * ? and the space character, all the rest can. A file or directory name can also have an optional extension, which can be no more than three characters long. If an extension is used, there will be a period between the name and the extension. Extensions are used primarily to let DOS and the user know what kind of data is contained within the file. Directories don't normally have extensions, but it's perfectly legal to do so; the only effect this would have is to allow you three more characters in the name.

COMPRESSION

Compression is where the computer reduces the size of files before storing them on the hard drive. This was done so that people could store more data without having to buy a larger hard drive. With the DOS compression program, called DRVSPACE.SYS or DBLSPACE.SYS (depending on the DOS version), you could compress a volume. All data currently on the volume would get compresses, as well as any new data you save to the volume. When performing the initial compression, another partition is created, it is called the host drive, DOS normally names this the H: drive. The host drive stores, in uncompressed format, information about the compressed drive. There's usually space left over on the host drive to let you store any files that need to stay uncompressed.

STARTUP OPTIONS

At times it might be desirable to start a computer but bypass the CONFIG.SYS and AUTOEXEC.BAT files. This would be considered a clean boot, and is useful for troubleshooting suspected device driver problems. To do this, press the F5 key or the SHIFT key while you see the message, "Starting MS-DOS. . ." on the screen.

Other times you might have the need to have most commands from CONFIG.SYS and AUTOEXEC.BAT carried out, but a few need to be ignored. Pressing the F8 key while you see the message, "Starting MS-DOS. . ." will put you into step-by-step confirmation mode. This will cause DOS to display every line from your CONFIG.SYS and AUTOEXEC.BAT file, one at a time, and will ask you if you want DOS to process that line. Useful if you suspect a specific driver is causing problems, so you just want to have that one driver be skipped (not loaded into RAM).

MULTIPLE CONFIGURATIONS

DOS 6.0 introduced the ability to create a menu inside your CONFIG.SYS file that would allow the user to choose a particular configuration to boot into. This would be useful if several people used the same computer, each had a need for different settings. Or if you had the need to have some device drivers not load some times, but load other times. You could add a few lines to your CONFIG.SYS file and DOS would display a menu every time your computer started up. A sample CONFIG.SYS file that uses two configurations follows:

1. [menu]
2. menuitem=Work, Work configuration
3. menuitem=Play, Gaming configuration
4. menudefault=Work, 30
5.
6. [common]
7. DOS=HIGH,UMB
8. device=c:\dos\himem.sys
9.
10. [Work]
11. device=c:\dos\emm386.exe
12. files=25
13. device=c:\cdrom\oakcd.sys /d:mscd001
14.
15. [Play]
16. files=40
17. buffers=15

First: the line numbers are for this discussion only, they are not to be used in a real CONFIG.SYS file.
Line 1 tells DOS to display a menu.
Line 2 creates a menu item with the label Work, but the phrase "Work configuration" will appear on the screen. The phrase is optional, if not used the label name will appear on the screen.
Line 3 creates a menu item with the label Play, but the phrase "Gaming configuration" will appear on the screen.
Line 4 tells DOS which menu item is the default (which one will be selected if the user doesn't make a selection, which in this example is the Work configuration), and to display the menu for 30 seconds. If no selection is made, the Work configuration will be automatically selected and booted into.
Line 6 defines a common block, which will be used no matter which menu item was selected.
Line 7 has DOS load a part of itself into the HMA, as well as keep track of UMBs.
Line 8 load the extended memory manager HIMEM.SYS, which is found in the DOS directory
At this point, DOS will now jump to the correct block, according to the selection the user made from the menu. So if the user selected menu item 2 (Play), DOS will now skip to line 15, and carry out the instructions on lines 16 and 17. If menu item 1 (Work) was selected, DOS would skip to line 10, and carry out the instructions on lines 11 - 13.

ISSUING COMMANDS USING THE PATH

The companion document, DOS COMMAND REFERENCE, lists a lot of commands that can be typed in at the command prompt. For simplicities sake, all the examples show the command working on a file or subdirectory of the current directory. In reality, you can issue a command while in any directory (and remember, you're always 'in' a directory) that works on files in any directory on your computer. To do so, you must supply the complete or relative path to the file you want the command to work on.

A complete path specifies every directory in between the root and the directory the file is in. An example: \PROGRAMS\MSOFFICE\WORD\DATA\LETTER.DOC

A relative path specifies every directory between the directory you are currently in and the directory the file is in. An example: If we were currently in the WORD directory from the above example, the relative path to LETTER.DOC would be DATA\LETTER.DOC

Let's show a few examples of actual usage. Lets assume we have the following directory structure:
C:\
|- DOS
|- CDROM
|- PROGRAMS
| |- MSOFFICE
| | |- EXCEL
| | | |- DATA
| | |- WORD
| | | |- DATA


Let's assume that right now we're 'in' the root directory. We could issue the following commands:
DEL \PROGRAMS\MSOFFICE\EXCEL\DATA\98BUDGET.XLS
Go the the DATA directory and delete the file named 98BUDGET.XLS.
MOVE \CDROM\MSCDEX.EXE \DOS
Go to the CDROM directory and move a file from there to the DOS directory.

COPY \DOS\COMMAND.COM .
Copy the file COMMAND.COM which is located in the DOS directory to the current directory (remember a single period is the shortcut that represents the current directory).
