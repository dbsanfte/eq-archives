WINDOWS 3.X

Windows 3.X, which includes versions 3.0, 3.1 and 3.11, were the first versions of Windows that sold in large quantities. Versions 1.X and 2.X had limited commercial success, they were used mostly as learning tools for Microsoft. Windows is a Graphical User Interface (GUI, pronounced GOO-ee). A GUI presents the user with graphical images, called icons, that represent resources (such as files, directories, volumes, and applications) on the computer. The user can use a pointer (an arrowhead displayed on the monitor),

controlled by a mouse, to let the OS know what the user wants to do. This made the computer much more user friendly than DOS was, since the user didn't have to learn a bunch of complicated DOS commands.

In the real world, Windows 3.X should be dead, but there are still people who have it installed on their computers (if it ain't broke. . .). You can no longer buy it, but you might occasionally come across a computer that has it installed, so there will be a handful of questions on the A+ test regarding Windows 3.X.

WINDOWS BASICS

Windows 3.X is not a stand-alone OS. A Windows 3.X computer will have some version of DOS as the primary OS, and the computer will boot into DOS first. Windows can be started by typing in WIN at the prompt. The whole name of the executable file that starts Windows is WIN.COM. Running WIN.COM (loading Windows) is also called starting a Windows session. Windows can be started at any time, and can be exited at any time - returning the user to the DOS prompt. WIN.COM contains a file called WIN.CNF, which is the actual executable code that starts Windows, and the graphic file that is the Windows logo that appears while Windows is loading.

When you run Windows, the main interface between you and Windows is the Program Manager (the file PROGMAN.EXE creates the Program Manager). You will see on your screen a Title Bar, a Menu Bar, and the Desktop with Program Group Icons. Program Group Icons will contain more icons that will be shortcuts to the various applications that you have installed in your computer.

OPERATING MODES

There are three different operating modes that Windows is capable of: Real, Standard and 386 Enhanced.

Real mode is essentially useless and obsolete. Windows, as well as any Windows based programs, ran inside the DOS 640KB memory space.

Windows detects your computer's CPU model (i.e. 286, 386) and will automatically run in the appropriate mode.

Standard mode was available on a 286 or higher system. Standard mode was achieved by having Windows send the command to switch the CPU into protected mode. In this mode Windows could access up to 16MB of RAM (a limitation of the 286 CPU's 24 address lines). Windows could also multitask - run more than one Windows based program at a time. Only one DOS based program could be run at a time. In order to access more than 1MB of RAM, HIMEM.SYS has to be loaded into memory via the CONFIG.SYS start-up file.

386 Enhanced mode was available on a 386 or higher system. This mode allows Windows to access up to 4GB of memory (32 address lines on 386 & higher CPU's), use virtual memory, and can run multiple Windows based and/or DOS based programs at the same time.

 

A DETAILED LOOK AT WINDOWS 3.X

There are three files that make up the core of Windows, KRNL386.EXE (or KRNL286.EXE for Standard mode) , USER.EXE, and GDI.EXE. These three files keep track of system resources, and allocate these resources to any active application that requests them.

    • KRNL386.EXE is in charge of allocating memory to active programs.
    • USER.EXE is in charge of devices the user will use to interact with Windows.
    • GDI.EXE (Graphics Device Interface) is in charge of the graphics on the screen.

These files use 64KB blocks of extended memory (called heaps) to keep track of which application is using which resource.

The term resource is used to describe two different things: the first is all the hardware that is available to Windows, the second is just the amount of memory available to Windows. The second definition is more important to know and keep track of - when memory runs out, Windows is stuck. To view how much memory resources you have available, click the Help menu from Program Manager, then select the About Program Manager menu item.

The boot process for Standard mode is as follows: WIN.COM loads DOSX.EXE to get extended memory support. DOSX loads KRNL286.EXE. KRNL286 loads Windows drivers (files that have a .DRV extension, and specified in the SYSTEM.INI file). Then GDI.EXE, USER.EXE, and any support files are loaded. Then the shell file is loaded (usually PROGMAN.EXE).

The boot process for 386 Enhanced mode is as follows: WIN.COM loads WIN386.EXE. WIN386 loads the Virtual Machine Manager (VMM) and Virtual Device Drivers (VxD, files with a .386 extension, and specified in the SYSTEM.INI file). Then KRNL386.EXE is loaded, which then loads GDI.EXE, USER.EXE, and any support files are loaded. Then the shell file is loaded (usually PROGMAN.EXE).

 

APPLICATION PROGRAMMING INTERFACE

API's make life easier for software programmers. Programs work by requesting system resources from the operating system. API's are standardized methods for application programmers to use to request resources from the OS. This way the programmers don't have to concern themselves with learning how to write code to issue commands directly to all the different pieces of hardware that they'll need to use.

DYNAMIC LINK LIBRARY

DLL's are files that contain a set of routine instructions. This makes life easier for programmers by reducing the amount of redundant code they have to write. A DLL file can be used by any program that needs the computer to perform the instructions that the DLL provides. Some DLL's are included with Windows, others are added to the computer when you install an application. Any program can use any DLL. This can cause problems: you install a program (we'll call it Program B), as part of the installation, Program B has a newer version of a certain DLL (we'll call it WHATEVER.DLL) that it installs. The problem could be that Program A was designed to work with the older version of WHATEVER.DLL. So when Program A runs, and makes a call to WHATEVER.DLL, there's new or different instructions in the DLL that Program A doesn't understand, and Program A generates an error or crashes.

WINDOWS AND DOS

Don't forget that a Windows 3.X system always starts in DOS first, then Windows loads. So the concepts you learned in DOS about startup files and memory management still apply. Whatever device drivers were loaded from the CONFIG.SYS and AUTOEXEC.BAT files will be available from within Windows. Windows has it's own startup files that serve the same purpose as CONFIG.SYS and AUTOEXEC.BAT do for DOS; these files are called initialization files (or INI, pronounced IN-ee, because the file extension is .INI).

INITIALIZATION FILES

Certain initialization files contain settings that Windows references while loading. Others have settings that a certain program references when the program is run. Initialization files are text files that are initially created when you install a program. Since they are in text format, they can be modified at any time using a text editor (like DOS' EDIT or Windows' NOTEPAD program). As long as the program, or Windows itself is running properly, there is no need to have to modify the contents of an INI file. As far as the A+ test goes, you'll just need to know the concept of what an INI file is for, and which ones Windows uses. The contents of an INI file is arranged into groups, with entries placed under each group that relate to the group heading. Each INI file will have it's own groups, there is no need to memorize them. Here are the INI files that Windows uses, and what each one is used for.

    • SYSTEM.INI: The most important INI file. This is the only required INI file. Serves the same basic purpose as CONFIG.SYS does for DOS - resources get initialized and settings that define how the resources are to be used get set.
    • WIN.INI: Keeps track of what personalized settings the user has chosen (like screen saver and color scheme), which fonts have been installed (and therefore Windows can display & print), file associations, and how resources interact with applications. You can add a line to this file that will cause a program to start running right after Windows is done loading. The RUN= command will have the application specified execute normally. The LOAD= command will cause a program to run as an icon only (minimized).
    • CONTROL.INI: Used to set colors, color schemes, and background patterns.
    • PROGMAN.INI: Used by the Program Manager to keep track of which Program Groups have been created and where they sit on the desktop.
    • PROTOCOL.INI: Used to set network settings such as the protocol used, and network card driver. Found only on Windows for Workgroups.

To modify all the Windows INI files at once, you can use a special program called SYSEDIT. This program will get all of the Windows INI files and bring them into a text editing window. The semicolon placed at the beginning of a line inside an INI file will cause that line to be ignored (just like REM does in CONFIG.SYS & AUTOEXEC.BAT).

VIRTUAL MEMORY

All 386 and newer CPUs have a protected mode of operation that allows the system to create and use virtual memory. Virtual memory is space on the hard drive set aside to pretend that it is RAM. This allows the user to have more programs running at the same time. The space on the hard drive that is being used as virtual memory is called the swap file, because data gets swapped into and out of the file as needed.

Here's an example of how virtual memory works. Let's say your computer has 32MB of RAM, and 30MB is used by Windows and the programs you currently have running. You start another application which requests 4MB of RAM. There isn't enough RAM to fill the programs request. Without virtual memory, you would get an "Out of Memory" error message. But with virtual memory, Windows will remove data from RAM and store it in the swap file on the hard drive, thus freeing up enough space in RAM for the program to run. You have no control over which data gets swapped, Windows manages that. All that you can control is the type of swap file and how large it is.

There are two types of swap files, temporary and permanent. Windows creates a temporary one by default. A temporary swap file only takes hard drive space while Windows is running; when Windows exits the swap file is deleted and the hard drive space is available for DOS' use. You can see the temporary swap file while Windows is running - it's named WIN386.SWP. The space on the hard drive that is being used for the temporary swap file doesn't have to be one contiguous block, it can be fragmented. A permanent swap file needs to be configured from the 386Enhanced icon in the Control Panel. It will need two files on the hard drive - SPART.PAR which points to the location of the actual swap file, and 386SPART.PAR which is the swap file. The space on the hard drive must be contiguous (non-fragmented), and it will always be in use, even when Windows isn't running. Windows must be running in 386Enhanced mode (which it will if your computer has a 386 or newer CPU) to be able to use a permanent swap file.

A permanent swap file will give your computer faster access to the data (than a temporary swap file), but will always be taking space on the hard drive.

A temporary swap file will be slower accessing data than a permanent swap file, but will not take up space on the hard drive when Windows isn't running.

Whenever your system has to use a swap file, it is slowing down your computer, since the hard drive is many times slower than RAM. RAM access is measured in nanoseconds, hard drive access is measured in milliseconds (slower). To stop your system from using a swap file, simply add more RAM, or don't have a lot of programs running at the same time.

 

MULTITASKING

Windows has the ability to multitask, which is running more than one program at a time. Windows uses cooperative multitasking. This form of multitasking puts the responsibility of multitasking on the applications themselves. They must be written to periodically give up control of the computer so if there's other programs running they get a chance. If an application was programmed by a novice or uninformed programmer, it might not include the code to periodically stop & let other programs get a chance, thus hogging all the computer's time. Technically, the multitasking that Windows does is really time-sharing. The CPU can only do one task at a time, but it does it very fast. So each program gets a little slice of the CPU's time before the CPU moves on to the next program, this happens many times per second. This gives the appearance that the programs are being executed simultaneously.

DISK CACHE & 32-BIT DISK/FILE ACCESS

A disk cache is RAM that is set aside to store data, on a temporary basis, that is read off the hard drive. When reading data from a hard drive, Windows will try to anticipate what the next file that will most likely be requested from the hard drive, and go ahead and get that file too. If the file is in fact requested, it is already in RAM, the system doesn't have to wait to have it retrieved from the hard drive. DOS' SMARTDRV program will work just fine from within Windows. To have SMARTDRV cache hard drives and CD-ROM drives, make sure to load SMARTDRV from the AUTOEXEC.BAT file after MSCDEX is loaded, otherwise SMARTDRV won't know there is a CD-ROM drive on your system.

32-bit disk access speeds up the system when reading from or writing to your hard drive. The only problem is that it is only compatible with older, basically obsolete hard drive controllers.

32-bit file access allows Windows to send commands directly to the hard drive to read/write data, bypassing DOS (which is has to do if 32-bit file access isn't selected). The file VFAT.386 is the driver that Windows loads that allows 32-bit file access. 32-bit file access also allows an improved disk cache program called VCACHE to operate. The size of the cache VCACHE creates is controlled by the 'Cache Size' box found on the Virtual Memory screen. VCACHE doesn't cache CD-ROM drives, so you'll still need SMARTDRV, but when you have both SMARTDRV will only cache the CD-ROM.

PIF FILES

A PIF (Program Information File) is a file that contains information that lets Windows know how to run a DOS program from within Windows. The information is stored in binary format, so you need to use the PIF Editor program to view and modify the contents of a PIF. A PIF stores, among other things, how much RAM (Conventional, EMS and XMS) the DOS programs requires, whether the program can run within a window or not, and which DOS executable file the PIF is storing settings for.

GENERAL PROTECTION FAULTS (GPF)

A GPF is usually caused by two applications trying to use the same memory location. This is caused by poorly written or corrupted software. Try re-installing the program that is causing the GPF, see if there is a patch available & apply it, or if all else fails, just don't run the two programs together.

SHORTCUT KEYS

There are a few shortcut keys that you'll need to know for the exam.

    • CTRL + ESC opens the Task List
    • ESC closes the Task List
    • ALT + ESC scrolls between open programs
    • ALT + F4 closes a program
    • F1 help
    • ENTER opens the selected icon (runs the program the icon is pointing to)

 

OTHER MISCELLANEOUS WINDOWS INFORMATION
  • Minimum hardware requirement for Windows 3.1/Windows for Workgroups (3.11): A 386 or better CPU, 2MB RAM and 8MB hard drive space.
  • The files SETUP.INF, APPS.INF, and CONTROL.INF supply information to the Windows Setup program.
  • The setup (SETUP.EXE) program goes through two steps: a text based and then a graphical portion. After the text based portion is done, Windows starts in Standard mode and it needs at least 192KB of XMS, so HIMEM.SYS needs to be loaded. If it isn't loaded, Windows will load XMSMGR.EXE to provide basic XMS support.
  • You can include several switches with the setup program.
  • /a will do an administrative setup - the files will be uncompressed off the floppies and copied to a shared directory on a server and be set to read-only.
  • /i will cause the setup program to skip the hardware detection phase.
  • /b enables monochrome display support.
  • /t will have the setup program search for incompatible software that shouldn't be run with Windows.
  • Upgrading Win 3.1 to Win95 will take about 30MB of hard drive space.
  • Upgrading Win 3.11 to Win95 will take about 20MB of hard drive space.
  • Raster/Bitmap/Screen fonts are not scalable, and will have a .FON file extension.
  • Vector/True Type fonts are scalable, and will have a .TTF or .FOT file extension.
