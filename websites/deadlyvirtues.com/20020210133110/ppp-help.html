Potted Intro to PPP

Redhat users may want to use netcfg to set up their PPP connection. This procedure should work on any version of Linux, though. For more on PPP see the PPP help section of the links page.

Preliminaries:

You'll need PPP support in your kernel. If you wish to use diald then you should also include SLIP support. For help on this see the Kernel HOWTO or the README in /usr/src/linux.

Setting up the modem

If the install procedure did not already create a soft link from /dev/modem to the serial port your modem is on (/dev/cua0 for COM1: or /dev/cua1 for COM2:) do so now.

Slackware users should first run setup to set up their modem and netconfig to set up loopback only networking.

If things are set up correctly then you should be able to dial out with minicom or seyon (you'll have to be root unless you set the permissions on /dev/cuaN differently.)

Adding the DNS numbers

Now add the dotted quad numbers for your ISP's DNS servers to your /etc/resolv.conf as in this example for cts.com: 

# /etc/resolv.conf

search cts.com 
nameserver 192.188.72.18
nameserver 192.188.72.21

If you've got your PPP connection set up under Win95, you can find the numbers under you networking properties. Otherwise, call customer support at your ISP and ask for the numbers. If you were assigned a static IP address then get that while you're at it. Now is also a good time to ask if there are any special login procedures for PPP accounts.

Creating the CHAT script

Now use minicom to dial you're ISP and record verbatim the prompts and responses neccessary to get PPP started. You'll use this to make your chat script. Save this in, for example, /etc/ppp/chatscript. The chat script below will probably work for most ISPs, though. If your ISP uses PAP or CHAP, consult the links in the PPP Help section. 

ABORT BUSY
ABORT ERROR
ABORT 'NO CARRIER'
ABORT 'NO DIALTONE'
ABORT 'Invalid Login'
ABORT 'Login incorrect'
'' ATZ
OK ATDT5551212
CONNECT ''
ogin: yourloginname
ord: '\qyourpassword'

The first part of this chat script defines strings that will cause chat to abort. The second part consists of expect/send pairs:

expect nothing/send command to initialize modem
expect OK from modem/send command to dial phone number
expect CONNECT/send nothing
expect ogin: (in case the l is dropped by line noise)/send login name
expect ord:/send password

The '\q' ensures that your password is not visible in the system logs.

Since the chat script contains your password, make sure that it is not world readable 
# chmod o-rw /etc/ppp/chatscript

Running pppd

Create the file /etc/ppp/options. It doesn't have to have anything in it for now, so just

# touch /etc/ppp/options

if the file isn't already there. Now you can start pppd. You can either log in as root each time to do this, or you can set the suid of the pppd binary

# chmod u+s /usr/sbin/pppd

We're ready to rock. For a dynamic IP address try 

$ /usr/sbin/pppd lock modem crtscts asyncmap 0 defaultroute  \
    /dev/modem 115200 connect "/usr/sbin/chat -f /etc/ppp/chatscript"
Here's a brief rundown on the options given to pppd above:

lock: use a lock file to ensure exclusive use of the device.
modem: use the modem control lines.
crtscts: use hardware flow control. (RTS/CTS)
asyncmap 0: do not escape the ASCII characters from 0x00 to 0x1F.
defaultroute: add a default route to the system routing tables, using the peer as the gateway.
/dev/modem 115200: communicate over the named device with the indicated baud rate.
connect "...": use the specified command to talk to the modem.

For a static IP address just add the dotted quad address on the line followed by a colon (you could add the route address after the colon, but we'll tell pppd take care of that with the defaultroute option.) 

$ /usr/sbin/pppd lock modem crtscts asyncmap 0 198.168.0.1: defaultroute  \
    /dev/modem 115200 connect "/usr/sbin/chat -f /etc/ppp/chatscript"

See the pppd man page for all the options to the pppd command.

To kill this you can use 

$ killall pppd

The next step would be to write scripts around these invocations. You should have the ppp-on and ppp-off scripts that come with the ppp package (in /usr/sbin on a Slackware system).
