What is Fara?

Fara is a simple DiabloII Single Player utility that creates HTML reports based on ATMA stashes or characters files. The reports contain a list of items which were found in the stashes and/or on the characters. The items can be organized in fully customizable categories and sub-categories (data file). The report can be further customized by arranging categories in rows and columns, and by chosing different colors and fonts for most elements of the report (styles file).

How do I install Fara?

Simply download and unzip the package in any directory to your liking. The package contains the executable, a settings file, and some examples of data files and style files.

How do I use Fara?

After starting the executable, you need to pick a data file and a styles file. Some examples are included. Then, you need to select a list of ATMA stashes and characters files which you want to parse. To create such files from ATMA:

1. Open a stash or character file.
2. Go to the "File" menu and select "Dump Partial Info". This creates a .txt file which can be used by Fara.
3. Repeat with as many stashes or characters as you like.

Once that's done, click "Generate report". If you've activated the "View output" option, you should see a new window summarizing the parsing process. Items that weren't recognized are listed there.

If you close Fara, all your settings will be saved and restored next time you start the utility. For more advanced usage, read the following two sections.

What's a data file?

Data files are customizable files that describe the items which you'd like to be included in the report. The items can be organized in categories and sub-categories. Categories can be organized in rows and columns. Each category can also be affected a different style.

Syntax:

**Name of first category[name of style][newcol or newrow]
*Name of first sub-category
Name of item,type of item
Name of item,type of item
Name of item,type of item
...
*Name of second sub-category
Name of item,type of item
Name of item,type of item
Name of item,type of item
...
**Name of second category[name of style][newcol or newrow]
...

Remarks:

1. Categories must be indicated by a double star (**).
2. Sub-categories must be indicated by a star (*).
3. There has to be at least one sub-category in each category, and at least one item in each sub-category.
4. The "type of item" is optional. This information doesn't serve any purpose internally; you could actually add anything there, such as personal comments.
5. The usage of styles is optional. If no style is specified, the default style will be applied.
6. The usage of "newcol" or "newrol" is optional. The "newcol" option starts a new column on the right of the existing data. The "newrow" option starts a new row at the bottom of the existing data. If no "newcol" or "newrow" is specified, data is printed in the current column.

Example:

**Normal Uniques[goldstyle][newrow]
*Helms
Biggin's Bonnet,Cap
Tarnhelm,Skull Cap
...
*Armor
Greyform,Quilted Armor
Blinkbat's Form,Leather Armor
...
**Exceptional Uniques[goldstyle][newcol]
*Helms
Peasant Crown,War Hat
Rockstopper,Sallet
...
*Armor
The Spirit Shroud,Ghost Armor
Skin of the Vipermagi,Serpentskin Armor
...
**Elite Uniques[goldstyle][newrow]
...

In this example, the categories "Normal Uniques" and "Exceptional Uniques" would be printed side by side, and the category "Elite Uniques" would be printed below. All three categories would use the style "goldstyle".

What's a styles file?

Styles files are customizable files that describe the colors, fonts and attributes that should be used to generate the report. They're actually standard CSS - Cascading Style Sheet - documents. They contain two sections. The first section contains the styles that are necessary for the report. You shouldn't change the names of these styles, but you can modify their attributes to your liking. The second section contains your own styles, which are used by the data file.
