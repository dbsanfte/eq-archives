Proxy Server

Description | Quick Start | Source Code

Description

The Proxy Server I wrote in Java allows you to provide TCP connections through a firewall. It offers simple encryption as well to prevent unwanted eyes from intercepting your communications. It is based on the fact that you have a server on the outside of the firewall and start the client on the inside. The client listens on whatever ports you wich and forwards each through a connection to the server on the outside to some host and port you specify.

I really wrote it to learn several things in the Java language: Threads, Sockets, Swing (JTable), and extending input and output streams.

Quick Start

You need to have at least JDK 1.2, or the Swing 1.1 classes installed for this to work.

Download the file now.

Run the server with the following command:
    java -classpath %CLASSPATH%;ProxyServer.jar com.goemaat.proxy.ProxyServerApp
You can change the port the server listens on from 110 by passing "-port <port>" on the command line, or select "Change Port" in the running program.

Run the client with the following command:
    java -classpath %CLASSPATH%;ProxyServer.jar com.goemaat.proxy.ProxyClientApp
To set the server, use the argument "-server <server:port>" or select "Change Server" from the program. Proxy sockets can be specified in the form "<type>:<listen port>:<server>:<server port>". The only currently supported type is "TCP", but UDP will possibly be supported in the future.

For instance, if you start the server on the computer "computer1.company.com" with the command:
    >java com.goemaat.proxy.ProxyServerApp -port 30000
And the client with:
    java com.goemaat.proxy.ProxyServerApp -server computer1.company.com TCP:23:computer2.company.com:23
You can then telnet from the computer the client is running on to localhost (itself) and you will be forwarded to computer2.company.com as if you telneted there directly.

If you pass the parameters "-encrypt <string>" to both client and server, they will use that string as a key to encrypt their communications. This will prevent any computers between the client and server from seeing the data your sending if they are sniffing it. This is a weak encryption algorithm, but not that easy to break either, especially if the person sniffing doesn't know this is the program you are using or doesn't have access to the source code.

Source Code

Classes in the package "com.goemaat.encrypt"

RandomGenerator - Class that produces very good random numbers (it has a period of 2^144).

Encrypter - Uses passwords combined with the RandomGenerator to encrypt an individual byte.

EncryptedOutputStream - OutputStream that encrypts bytes with the supplied passwords using an Encrypter object.

EncryptedInputStream - InputStream that decrypts bytes with the supplied passwords using an Encrypter object.

Create an EncryptedOutputStream at one end of a socket and an EncryptedInputStream at the other end with the same passwords and you have a pretty secure connection. Can also be used to wrap streams to/from files.

Classes in the package "com.goemaat.Proxy"

ProxyClientApp - Client Application that retrieves command line arguments and handles managing the threads.

ProxyClientFrame - Frame that displays the working and listening connections and allows you to change the server, remove worker connections, add listening connections, and remove listening conenctions.

ClientListenThread - Thread that listens on a port for incoming connections and creates new ClientWorkThread objects for each incoming connection, which are added by calling ProxyClientApp.addWorkerThread().

ClientWorkThread - Thread that connects to the proxy server and handles forwarding the data both ways for the life of the connection.

ProxyServerApp - Server Application that retrieves command line arguments and handles managing the threads.

ProxyServerFrame - Frame that displays the working and listening connections and allows you to change the port the server is listening on.

ServerListenThread - Thread that listens on a port for incoming connections and creates new ClientWorkThread objects for each incoming connection, which are added by calling ProxyClientApp.addWorkerThread().

ClientWorkThread - Thread that connects to the proxy server and handles forwarding the data both ways for the life of the connection.
