Welcome to the EQWatcher home page.  Yes it sucks I know.  Deal with it.

Like using EQWatcher?  Vote for the site on the EverQuest Top 200 by clicking on the link below, if you want.  I don't really care it's just for fun :)  (Note: Before I had this link on my site, the EQ Top 200 had only 30 or so sites, and no site had more than 9 votes.  Thanks for supporting the EQ community :))

EQWatcher is designed to give audio cues for events within EverQuest. In a nutshell, this program watches your eq chat log (eqlog.txt for instance) and interprets what is going on. Additionally, EQWatcher will monitor the eq notes file (notes.txt) for commands directed to it. EQWatcher currently supports up to 50 timers, and 256 triggers, each completely customizable. As a triggered sound EQWatcher is currently capable of playing a WAV file, a CD track, an MP3 (MP3 support is strictly via WinAMP), or Text to Speech (TTS support is strictly via Microsoft Speech API).  EQWatcher is very versatile and anyone can create features such as the included damage calculation.  Please see the Introduction to EQWatcher for this and other information, and please visit the EQWatcher Message Board for news updates, bug reports, and what the people who HAVE used EQWatcher have to say.

Please note that EQWatcher WILL NOT EVER do anything automatically for you within EverQuest.  I get asked about supporting this over and over and the answer is always the same.

EQWatcher Advanced BETA 6

Beta 6 has been re-built and re-released to fix some bugs.  Please download Beta 6R2 if you are currently using Beta 6.

Lots of new stuff in Beta 6 too.  For one thing, triggers and timers you wanted to convert from EQWatcher 1.76 that, in beta 5, required writing script.. no longer require this (for the most part).  The new process is in the documentation.  There is now a user interface for the compiler to make recompiling the core script or other scripts easier.  Beta 6 is being released earlier than planned to correct some reported bugs and some (highly) potential crashes.

Note to script developers:  Beta 5 scripts will need to be recompiled for Beta 6.

Changes to Beta 6 include:

  • Speak buttons added in Pronunciation Guide editor
  • User will have a choice regarding pausing WinAMP for synchronous sounds. Possible choices: do nothing, lower volume, or pause
  • Fixed "set combatant" command
  • Added a separate "set combatant" command for clearing it back to "You".. so "set combatant " and "set combatant" both are basically just short for "set combatant You"
  • TRIGGERS and ALIASES will no longer be case-sensitive. Variables will retain the original case.  This means triggers that should hit on "BRD" now hit on "brd" "bRD" bRd" "Brd", etc.
  • Ability to execute an alias directly from a trigger
  • Script management interface for main program (pick compiled scripts to load on startup, ones for each character, etc)
  • Ability to execute an alias from a compiled script -- new command is Execute(string command)
  • Fixed bug as reported in interpreter for LoadPG, LoadScript, LoadCommands
  • CHANGED FORMAT OF TRIGGER AND ALIAS ADDING IN CORE SCRIPT. Command files must be updated accordingly. The change removes quotation marks from the sound information given. This is done so triggers can make timers via the timer adding aliases without running into problems with the quotation marks. Now unless it uses a variable, timers that start from triggers don't necessarily need to be written into a compiled script.
  • Ability to un-load scripts (note: script unloading is implemented for specific sets per character as well). Script command is "UnloadScript(string filename)" and the alias is 'unload script "[filename]"'
  • Created a *simple* front-end for compiler so people will not have to use the command prompt
     

EQWatcher Advanced BETA 5

Quick note to Beta 4 users: the waypoints files have changed.  They are now stored in the "Waypoints" directory.  If you used the navigation system previously, you *will* need to create your waypoints again.  The old .WAY files in the EQWatcher Advanced directory were being corrupted when updated waypoint locations were shorter or longer (i.e. -3 compared to -3000).  The new version prevents this corruption, but will not work with the old files. 

Lots of new stuff in Beta 5 :)  Several bugs were fixed in the core script (which handles all of the basic functionality), and I've also added MOST of the old .WAV sounds to it as well.  I'm almost positive that all of the sounds from EQWatcher 1.76 are now in EQWatcher Advanced Beta 5, for all of you without Text-to-Speech.  I have also documented ways to convert your EQWatcher 1.76 timers and triggers to EQWatcher Advanced (some will be easier than others) -- I will release a utility to do this automatically within a few weeks as well as Beta 6.  Beta 6 will be considered the first release candidate, and if few enough bugs are found EQWatcher Advanced will go "gold" and will replace EQWatcher 1.76 as the main download.

EQWatcher will now automatically detect DirectSound and use it for .WAV playback (although not for Text-to-Speech (TTS) unfortunately -- this will not hinder anyone already enjoying TTS in EQWatcher.  See the "Whats in Beta 5" thread on the announcements message board for the reason why DirectSound doesn't currently mix with TTS).  Hopefully this will allow users with low-end or just plain old sound cards to magically be compatible with EQWatcher.  If you were previously unable to use EQWatcher, or limited by workarounds, let me know how this works out (these users will need to use the disable TTS command if they have TTS installed, see the Miscellaneous Commands section of the EQWatcher Advanced documentation).

One last thing I would like to mention is about sharing scripts (and other things such as sounds) with the community.  Any user can submit scripts or modifications to already available scripts to me in email to put on the downloads page.  While property of a script becomes mine and the EQWatcher community's, credit is given where due and you may request your script be removed from the site (and I will most likely honor that request).  I do reserve my right to make modifications to your submitted scripts, not hindering their performance -- credit will be given where due, and any modifications I make will be branded with my name, and possibly added under yours at the top of the script.  I also reserve the community's right as a whole to do the same, which may then be submitted to me in email for updating on the downloads page.  For more rambling about this topic see the "Beta 5 to be released TONIGHT" thread on the announcements message board.

Information regarding Windows XP

I have tested EQWatcher with several versions of windows, including Win98, Win2000, and recently Windows XP.  Under Windows 2000 and Windows XP you will want to configure your computer to run BACKGROUND SERVICES efficiently (by default they give much much more CPU time to EverQuest and this will cause sounds to be played very slowly and even break up... in Windows 2000 there's not much hope if your EQWatcher sounds skip though).  In Windows XP: find the system control panel (system properties), and select the Advanced tab.  In the "Performance" frame click Settings, and in Performance Options select the Advanced tab.  Under "Processor Scheduling" click on "Background Services" and click OK.  The process in Windows 2000 is slightly different but I haven't used win2k in a few months, so I can't give detailed instructions.

And as you may or may not know, Windows XP comes with the Microsoft Text-to-Speech engine already installed.  This means that Windows XP users can use the speech capabilities without downloading the SDK from Microsoft.  In current testing, the speech may be slightly broken up.  I will try to do some more testing with this...

EULA Information Updated

Someone let me know my EULA information was out of date (the only difference in my quote being part of the old #8 is the new #9), and in my searching I found more useful information on the topic.  Quick reminder that I do not support any action that would violate the EULA, including the Rules of Conduct.  The portions of these rules that deal directly with usage of EQWatcher are as follows:

#5 "You may not modify any part of the EverQuest Client, Server or any part of the EverQuest Web Page located at http://www.everquest.com."

#11 "You will not attempt to interfere with, hack into, or decipher any transmissions to or from the servers running EverQuest."

Again, EQWatcher was written specifically to NOT violate the set rules while offering some audio cues to events in the chat log.  The chat log is not a transmission to or from the servers running EverQuest, nor is the notes file.  EQWatcher does not modify any part of the EverQuest Client, Server, or Web Page.

The EULA portion of the Introduction to EQWatcher has been updated accordingly.
