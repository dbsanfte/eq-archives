What is EQWatcher?

EQWatcher is designed to give audio cues for events within EverQuest. In a nutshell, this program watches your eq chat log (eqlog.txt for instance) and interprets what is going on. Additionally, EQWatcher will monitor the eq notes file (notes.txt) for commands directed to it. EQWatcher currently supports up to 50 timers, and 256 triggers, each completely customizable. As a triggered sound EQWatcher is currently capable of playing a WAV file, a CD track, an MP3 (MP3 support is strictly via WinAMP), or Text to Speech (TTS support is strictly via Microsoft Speech API).

Installation

In version 1.5, the installation process has been updated to be almost idiot proof.  Previously, EQWatcher would pop up a series of windows the first time run, asking you to direct it to the location of a few programs (EverQuest, EQWatcher, and WinAMP).  In MOST cases, this will no longer happen.  HOWEVER, in some cases, where these programs have not been installed using the actual installer, the windows will pop up.  If EQWatcher detects the wrong directories, you can still set them manually in the file menu.  For informational purposes I have left the old installation process below, which will be either modified or removed later on as I update this introduction.
 
The first time you run EQWatcher, it will pop up some windows that require your help in finding some directories (or folders as you might say). First it pops up a window looking for "eqwatcher.exe", this is to locate your EQWatcher directory.  Next it pops up a window looking for "eqmain.dll", this is to locate your EverQuest directory and does not in any way actually access this file.  Then it pops up a window looking for "winamp.m3u", this is to locate your WinAMP directory.  If you do not have WinAMP, you can just hit cancel.  Previously, EQWatcher would next pop up a window looking for "eqlog*.txt", this was to pick which log file you want to start out using.  EQWatcher now automatically uses the most current log file found in the EverQuest directory and will continually watch this.

These four options are saved in a file called OPTIONS.EQW in the EQWatcher directory, and each may be changed within EQWatcher in the File menu. If you delete this file it will reset the above settings, and EQWatcher will pop up the dialogs for you again.  This and ASSIST.EWC are the only EQWatcher data files that are not easily changed with a text editor (examples: notepad, edit).  ASSIST.EWC is used in the assistance window to help you execute commands from outside of EQ.

Using EQWatcher

EQWatcher is becoming easier for newcomers to use effectively.  Recent developments in the user interface and scripting capabilities (please keep in mind that any talk of scripting are merely collections of EQWatcher commands, and will not EVER do ANYTHING automatically for you within EQ) are helping to convert EQWatcher from a strange collection of odd looking programming style commands to a more user friendly tool.
 
Many people are undoubtedly interested only in certain capabilities of this program, such as the Damage and Damage Per Second scripts.  Use of these scripts and features now requires very little knowledge and can be fully configured and used via hotkeys/socials.  These socials can be imported directly to your character by using EQHotkeys, which is included with EQWatcher.  You will want to learn how to use EQHotkeys to import the social banks from EQWatcher\Scripts\Damage2.  EQHotkeys should be fairly straightforward, most of the buttons are made to look similar to their inside-EQ counterparts and can be easily imported.  See the file EQWatcher\Scripts\Damage2\using this script.txt for specific information on using the actual socials.
 
Some things of interest not found anywhere else in the intro yet... Upon loading, EQWatcher runs a script called STARTUP.EWS.  Upon finding a new current character, EQWatcher first runs a script "charname_##_end.ews" using the last character, then runs a script "charname_##_begin.ews" where charname is your current character's name, and ## is the server number.  This format is derived from the log file name that looks like "eqlog_##_charname.txt".  Scripts are considered an advanced feature - writing scripts and use of variables is discussed in a later section titled "Scripts and Variables".
 
In version 1.75, aliases were introduced.  This provides shortcuts for executing many of the existing commands, even allowing variables to be set in the meantime.  A two line sequence that first sets a variable and then runs a script can now be placed into one single command.  Running your favorite script can now be done with a single word command.  See this message board thread for some related info on aliases.. Please note that aliases do not yet get saved to any file, so you will want to write "add alias" commands into your startup.ews or character begin scripts.
 
Soon I will create separate information for the general and advanced features, but below you will see the section as it used to appear.  It may seem confusing or difficult to understand, but most of this knowledge is not needed to use the basic features of EQWatcher. 
 
Using the main features of this program might seem difficult at first, however once you have used it, it will all come clear. I will try to update this introduction for the new version in the next few days, since a lot of the ideas explained may not apply anymore.  Please read the sections titled "How do timers work?" and "How do triggers work?" for specific information regarding them.

All of the trigger and timer properties can be edited at any time using a simple text editor (example: notepad). The default names for the files are TRIGGERS.EQG and TIMERS.EQM, but you can have any number of separate files with different trigger and timer sets. You will be able to load any set at any time and save to new filenames while in EverQuest.  

There are also built-in triggers based on channel communication. Each channel may be turned on and off independently or you may turn them all on or off at once. Says and Tells are set to bark, and the other channels are set to squeak. The default sounds for these can be changed by editing STARTUP.EWS.

Some of your triggers and timers you might want to edit outside of EverQuest in a text editor, for the simple fact that anyone can come along and say something to trigger it, if they are devious and know you're running EQWatcher and know your triggers and want to mess with your head.  In order to protect against this, EQWatcher will watch for the end of the time/date stamp as the beginning of the line of text.  If you look at a line of a log file it says something like [blah blah blah blah blah] Logging to eqlog.txt is ON.  Well, try typing in a right bracket ] in EQ and it won't let you (note: it lets you if you are making hotkeys).  So, when you are editing triggers you can start them off with a "] " to watch for the beginning of the line.  The included sample triggers and timers use this to their advantage.

Scripting is something new to version 1.10.  A script is currently just a bunch of EQWatcher commands put into a file, so many commands may be stringed together into one.  You can execute one of these scripts from the EQWatcher interface, from inside EQ, or as a response to a trigger or timer.  Writing scripts and use of variables is discussed in a later section titled "Scripts and Variables".

Another feature new to 1.10 is when you minimize EQWatcher, it becomes a system tray icon.  Double click that icon to restore the window.


Okay, now I think you might want to know how to control EQWatcher from within EverQuest. Here is a list of commands available. Each command is executed in the same way, and must all be done in lower case. To do one of these commands, type /note followed by the command. This will add a line to your notes.txt file for EQWatcher to interpret.  There are commands specifically for use with timers and triggers listed as well.

How do I format sounds?

Playing a .WAV:  Use the complete path name to the .WAV (ex: C:\Windows\Media\ding.wav ).  You may use a relative path name such as "Sounds\danger.wav" as well. 
Playing an MP3:  Use the format #[keywords] (example: set sound '#Metallica', set sound '#one metallica', set sound '#Joe Satriani'.  EQWatcher will attempt to match each of the keywords given.  If all of the keywords match, in any order or case (i.e. "A" is the same as "a").  If no match is found it will not switch songs.
Playing a CD Track: Use the format *[track number] (example: *12)
Running a script: Use the format ^[filename] (example: ^Scripts\script.ews)
Executing an EQWatcher command or alias: Use the format -[command] (example: -stop cd)
Using text-to-speech: Use the format ![text to speak] (example: !hello, my name is joe)

How do timers work?

Timers are EQWatcher's way of warning you of something that is about to happen.  This can be anything from timing the length of clarity and saying "Clarity" when it must be recast, to timing the length of a spawn and giving an audio warning.  EQWatcher currently supports up to 10 of these.  The way it works is when EQWatcher finds the timer's trigger in your log file, it remembers exactly when it saw it.  When the timer's set length of time is up, it plays a sound you select.


Right now the only way to make new timers or modify existing ones is by either editing a text file containing timer information (TIMERS.EQM by default), or by giving the command within EverQuest.  You can load timer sets from EQWatcher's File menu, and you can load and save timer sets to your own file names from within EQ as well.


Timers have the following properties
- Active state (0 or 1 meaning off or on)
- Keyword
- Sound
- Timer length in milliseconds  ** note: when setting the length from in EQ you give mins:secs
- Main Trigger Text
- Alternative Trigger Text
- Placeholder Trigger Text


When formatting a new timer (the only time you ever need to know this is if you are editing the timers file.  You do not add timers within EQ, only change the 10 existing ones.  Look at TIMERS.EQM for the default keywords, etc) it should look something like this. As you can see, each property is listed and separated by a semi-colon ";"
0;timer1;*1;1175000;Main trigger;Alternate trigger;Trigger for placeholder


The keyword is used for accessing the timer within EQ.  When you want to change this timer you will need to know the keyword.  You can change it at any time.


The active state property identifies whether or not the timer will actually start timing or play its sound.  You can always access an inactive timer for anything else.


The placeholder trigger on a timer is only used when the placeholder flag is turned on, and is completely ignored if it's off.  The reason for the trigger and flag are because there are many placeholders possible for each rare spawn, and making EQWatcher look for every single one is just out of the question.  Therefore it is usually good to watch for a generic message such as faction hits, and only watch for them at a specific time -- such as while you are fighting the placeholder.  When a placeholder spawns instead of rare spawn, turn on the placeholder flag and it will look for all 3 of the triggers (main, alternate, and placeholder) as opposed to just main and alternate.  When any of the 3 hit, the placeholder flag is then turned off again.  If this does not suffice you always have the option of manually starting the timer.


All of the timer commands are listed in the Commands Reference.

How do triggers work?

Triggers are used for when you want EQWatcher to respond to something at the exact moment it happens.  This is useful for anything from a warning when "You feel yourself starting to appear." to a simple sound when someone says "heal me".

Right now the only way to make new triggers or modify existing ones is by either editing a text file containing trigger information (TRIGGERS.EQM by default), or by giving the command within EverQuest.  You can load trigger sets from EQWatcher's File menu, and you can load and save trigger sets to your own file names from within EQ as well.


Triggers have the following properties:
- Keyword
- Trigger Text
- Sound


When formatting a new trigger it should look something like this.  
As you can see, each property is listed and separated by a semi-colon ";"
invis;] You feel yourself starting to appear.;sounds\danger.wav


A quick reminder that you cannot actually type a ] in EQ, you must edit these into the trigger using a text editor.


The keyword is used for accessing the trigger within EQ.  When you want to change this trigger you will need to know the keyword.  You cannot currently change a trigger's keyword within EQ, so just remove it and add a new trigger if you need to do this.  You can, however, change the sound from within EQ.

All of the trigger commands are listed in the Command Reference.

Scripts and Variables

Scripting is a brand new subject to 1.10 and this section will cover the advanced topic of writing scripts and using variables.  Please keep in mind that these scripts do not and will not ever perform actions that may be a violation of the EQ user license (I say this because some people will automatically think "script? Can I make it hit buttons for me?" and the answer to that is no, definitely not).  An EQWatcher script runs linearly, that is, each command is executed in the exact order as read from the script file.  No prefix is needed (such as /note) for these commands.  Scripts can run ANY EQWatcher command, not just the ones listed under script commands.  The reason I made two seperate lists is to direct people toward the simpler commands and away from the advanced commands.

Variables are values that EQWatcher remembers and can recall or change.  They can all be either strings of characters up to 255 in length or a number from about negative 2 billion to positive 2 billion.  Variable values can be used in any command to be executed (using the format %variablename%), and are processed before execution (to instruct EQWatcher NOT to pre-process the variables, use the prefix # to your command... such as #add trigger, or #add alias).  Variables can also automatically be set by triggers and timer triggers by using the format @variablename@ for setting a string or @!variablename@ for setting a number.  The same format for setting variables can also be used in creating aliases.  You do not need to initialize variables before use, EQWatcher will automatically initialize them -- however, if you need to set a value you may initialize a variable using set string or /set int.  

Variable mathematics are currently in a very primitive state.  You may add, subtract, multiply, or divide a variable with another number.  It is possible to do more complex mathematics by breaking your equation into steps, and using the "math" command for each one.  Obviously some things may take separate variables to calculate.

Scripts may be commented on empty lines by starting the line with a semi-colon (;).  These comments are very important for helping others (and even yourself) understand the script.

Since EQWatcher scripts are currently executed linearly, complex scripts will need to use multiple files to do their deed.  The new sample damage counting script demonstrates a very complex script and how it uses variables.  I would suggest taking a look at the sample scripts for examples and further help.
